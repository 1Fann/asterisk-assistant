# Asterisk 助手 / Asterisk Assistant

**Current build: 1.2.5** — [新手机部署与权限说明 / New-phone setup](NEW-PHONE-SETUP.md)

内置 AGI 空姓名号码分段修复；跨 Root 管理器部署；公网 IPv6 Wi-Fi 接收锁及可关闭的 Android 11–13 息屏兼容，替代迁移时的外置补丁。

[English](README.en.md) · [下载 APK](https://github.com/1Fann/asterisk-assistant/releases/latest) · [MIT](LICENSE)

在已 Root 的 ARM64 Android 手机上，一键部署并可视化管理 Asterisk SIP 服务器。当前版本 **1.2.5**。这是社区原创管理 App，使用 Ubuntu 软件源的 Asterisk，未修改服务器核心源码。无需 Termux。

1.2.0 修复空主叫名称在 AGI 中表示为 `unknown` 时跳过号码分段的问题；仍保留真实联系人姓名及号码隐藏设置。

- 一键下载安装经校验的运行环境；启动、停止、重启。
- SIP 账号、密码、连接状态、端口、拨号配置和备份管理。
- 日志、认证与 RTP 回声自检、旧部署迁移清理。
- 开机启动、可选唤醒锁、独立服务器定时检查与异常恢复。


## 引擎恢复优化 1.2.5

每秒检查缓存进程是否退出。确认原服务器引擎已退出、管理服务仍在前台时，完成原签名、运行组件完整性、授权开关与实时通话检查后，直接恢复引擎，随后继续完整后台和 SIP 检查。无法确认状态时回到原恢复流程。手动停止先写入停用标记，启动与停止共用互斥锁，自动恢复不会清除停用标记。

网络准备只在一次成功执行前后，IPv4、IPv6、完整 SIP 配置、公网开关及相关代码的哈希均未变化时缓存。以后全部一致可省去重复准备；任一变化或准备失败均重新处理。启动后的固定三秒等待改为在原预算内观察真实进程，最终仍要求 SIP 响应。恢复目标约三秒，实际耗时需在设备上验证；通话中和状态未知时暂停恢复，不承诺任何故障都能三秒恢复。

## 启动准备优化 1.2.4（本地构建）

启动和开机恢复会先验证助手签名、已成功部署的 APK 版本戳，以及运行脚本、开机钩子和 rootfs 副本的 SHA-256、Root 归属与脚本执行权限。全部匹配时复用现有组件，省去每次启动的资源解压和重复复制；版本变化、文件缺失或损坏时完整重新部署组件。更新和一键部署仍强制刷新。保留原唤醒开关、手动停止和通话保护；此优化的真机恢复时间需另行测量。

## 可靠性加固 1.2.2（本地构建）

健康检查增加独立的单实例监护父进程，检查工作进程异常退出后自动重建；两个助手共用的恢复锁改为非阻塞获取，争用时短暂等待后重试，避免永久卡在锁上。系统服务轻检和开机状态查询设有超时。运行脚本通过原子替换更新，避免刷新时截断正在执行的脚本。Asterisk 的开机及系统重建入口尊重手动停止，关闭开机开关可以结束等待。

保留既有通话保护、签名校验、检查间隔和唤醒开关；不会自动整机重启或绕过首次解锁。父进程自身或整个设备失效、无唤醒能力的深睡以及外部网络故障仍需独立监测，不能保证零中断。隔离回归覆盖锁争用、重复启动、工作进程被杀后的恢复及关闭退出；真实长时间息屏和有密码的重启仍需验收。

## 上次更新 1.2.1

同时修复安装名称乱码，添加自适应服务器应用图标。

已确认的故障是系统限制后台运行 / 小米自启动关闭，以及状态检查仅看到旧注册状态。不是单纯检查间隔过长。

首次打开助手时显示“后台运行准备”。点击“检查 / 允许后台运行”并明确确认后，助手仅为自己及受信任的配套网关解除后台限制、加入电池优化白名单，并在可识别的小米系统允许自启动。电话、麦克风、通知及 Shizuku 权限仍需用户自行允许。遇到不支持的系统设置时说明具体失败项，不再统一提示 Root 失败。

自动检查开启时，每约 10 秒轻量检查服务是否退出；完整检查仍按用户配置的 1–1440 分钟执行。授权后台设置后，检查任务可修复被重新施加的后台限制。Asterisk 与网关的恢复仍分属各自助手，共用恢复锁；通话中或无法确认通话状态时不重启，尊重应用内手动停止。清理最近任务无需加锁，但被杀进程恢复期间仍可能暂时无法接听，不承诺零中断。

专用唤醒锁继续由 Asterisk 的原有开关控制。开启时，Root 检查任务持有可续期、到期自动释放的唤醒锁，防止界面被清理后检查立即休眠；关闭时释放。DDNS 的独立守护和唤醒选项保持原状。

## 检查与恢复

可独立开启、关闭，间隔1–1440分钟（默认5），支持立即检查和上次结果。Root 检查任务独立于界面，清理后台后仍能检查；开机首次解锁后恢复。通话中或无法确认通话状态时跳过恢复，Wi-Fi 未就绪时等待。关闭检查不会停止现有服务。深度休眠可能延后检查；清理至下次检查之间可能短暂不可用。

本助手只恢复服务器进程、前台网络服务、SIP 响应及 Wi-Fi 地址变化。网关与 Shizuku 由 [Voice SIP 助手](https://github.com/1Fann/voice-sip-assistant) 独立管理。手动点击“停止”后，服务器监护不会把它拉起。必要时恢复后台服务可能打开管理页面。两个监护任务共用锁，避免同时修复。

## 使用

1. 安装 APK，允许通知并授予 Root。需要 Android12+、ARM64、约1GB空间，以及 Root 管理器提供的 BusyBox（自动识别 Magisk、KernelSU/BakaSU、APatch 路径）；已在 Android 13 / Magisk 红米和此前 BakaSU 红米上验证相关部署。
2. 点击“一键部署 Asterisk”。初始客户端账号1001、网关账号2001，密码由本机随机生成。
3. 从“账号与连接方式”读取本机连接参数。初始 SIP UDP16060、RTP22000–22019，可在界面修改；迁移安装以界面实际值为准。
4. SIP 客户端拨600验证回声。初始安装不会自动添加真实蜂窝呼出路由。
5. 按需开启自动检查并保存间隔。卸载前关闭检查、停止服务器。

Root 数据位于 `/data/adb/asterisk-app`，服务器使用普通 App UID 运行。账号只保存在本机，不上传云端；不修改路由器。

## 自行构建与签名

Windows、JDK21、Android SDK35、Build Tools36.0.0：

```powershell
./build.ps1 -SdkRoot C:/Android/Sdk -JavaHome C:/Java/jdk-21
```

构建脚本在本机 `private/` 生成签名文件。公开发布 APK 使用维护者的既有签名，可覆盖升级已安装版本；CI 使用临时签名，只验证构建。自行签名需要同步修改代码中的证书指纹：Asterisk 的 `RootBridge.CERT`；Voice SIP 助手的 `Root.DUALSIM_CERT`（其自身及配套网关信任指纹）。不同签名不能直接覆盖安装。私钥、密码和手机配置不在仓库中。

## 内置来电号码分段（1.1.2）

号码格式化脚本和 Google libphonenumber 的完整轻量号码库已内置 APK，包含 245 个国家／地区的号码数据。首次部署会自动准备，覆盖升级后打开 App、授予 Root，空闲时自动接管现有配置；不再需要电脑 ADB 或独立部署 ZIP。

在首页“可视化管理 → 来电号码分段”可以开关功能，并修改默认地区（默认 CN）。带国家区号的国际号码自动识别；无国家区号时按默认地区处理。支持手机、固话、400／800 及国际号码，分隔符统一为空格。

只调整数字形式的显示名称，保留真实号码、隐私状态和文字姓名。号码处理离线进行，短号、服务串和无法识别的号码保持原样。通话中或通话状态不明确时推迟自动配置，空闲后重试。开关保存需要在空闲时进行。

新部署仍是回声测试环境，不会自动创建蜂窝通话路由；后续配置的本机认证网关上下文会自动包裹格式化入口，保留原上下文的拨号优先级。已有独立分段脚本会原位接管，避免重复执行。不承诺与 iPhone 原生电话的排版完全一致。[旧版独立部署工具](tools/callerid-format/README.md)仅作为备用方案保留。

## 公网 IPv6 / DDNS（1.1.1）

部署后打开“公网 IPv6 / DDNS 域名”，填入你自己的完整域名并开启。原 DDNS 服务继续管理 AAAA；Cloudflare 使用“仅 DNS”。客户端的域名不加端口，SIP 代理填 `sip:phone.example.com:端口`，UDP，原用户名、认证 ID 和密码保留。

- 将管理的客户端账号切换到非临时 Wi-Fi 公网 IPv6，SIP 和 RTP 使用同一地址；本机网关继续使用 IPv4 回环。
- 公网模式下客户端需要 IPv6；原 IPv4 客户端应改用域名。关闭公网模式后恢复局域网客户端设置。
- 自动检查跟踪 IPv6 变化，空闲时重启更新监听及语音地址；没有可用公网 IPv6 时回退局域网，待地址恢复再更新。保持自动检查开启。
- 服务持有 Wi-Fi 组播接收锁，以兼容部分 ROM 的息屏 IPv6 寻址。会增加耗电；关闭公网模式、停止服务或进程退出时释放。
- 自检支持 IPv6 账号认证及 RTP 回声；不会自动拨打真实蜂窝电话。沿途防火墙需允许界面显示的 SIP UDP 和 RTP 端口，不会自动修改路由器。
- 当前预设使用 UDP，未配置 SIP TLS 或媒体加密。管理页面、账号密码和配置仅保存在本机。

本次设备验证：公网蜂窝网络域名登录及回声由用户确认；短时息屏的跨设备 SIP 和 ICMPv6 通过。长期深度休眠、重启及完整双卡公网通话仍需实测。

## 1.2.3 本地恢复速度改进（2026-10-31）

首次检测工作进程退出立即重建，连续快速退出才逐步退避。每秒仅使用缓存 PID 做存活检测，网关或 Asterisk 引擎退出会立即请求原有安全检查；前台服务检查仍每 10 秒执行。网络和依赖暂未就绪时，前 6 次在 3 秒后复查，随后降低频率。开机等待已解密存储和网络改为每秒检查。升级交接先等待正在执行的恢复检查结束，再更换监护进程。

这些时间是检测触发和隔离测试阈值，不等于通话全链路恢复时间；通话状态未知或忙碌、手动停用、签名验证和首次凭据解锁要求保持原有规则。
